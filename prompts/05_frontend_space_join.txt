역할: React 프론트엔드 엔지니어.
선행 단계: 04_artifact_upload_api.txt 까지 백엔드 API가 동작해야 한다.
이번 단계 목표: 로그인 없이 스페이스를 만들고 코드로 입장하는 화면을 완성한다. (F1 UI)
다음 단계: 06_frontend_upload_layout.txt

================================================================
제품 컨텍스트
================================================================
참여자는 닉네임 + 소속(학교/전공)만 넣고 들어온다.
소속은 나중에 마인드맵 노드 색상으로 "전공 간 교류"를 보여주기 위한 데이터다.
폼은 짧고 빨라야 한다. 해커톤 시간 절약이 설계 이유다.

================================================================
화면
================================================================
1) 홈 (/)
   - 앱 이름
   - 한 줄 카피: "각자 올리기만 하면, 정리는 알아서 됩니다"
   - [스페이스 만들기] [참여 코드로 입장]

2) 스페이스 생성 (/create)
   - 주제 입력 1개
   - 성공 시 참여 코드가 큰 글씨로 보임 (복사 버튼)
   - 이어서 본인도 join 폼을 작성해 스페이스로 입장

3) 입장 (/join)
   - 6자리 코드, 닉네임, 학교, 전공
   - 성공 시 /spaces/:spaceId 로 이동

4) 스페이스 셸 (/spaces/:spaceId)
   - 상단: 스페이스 이름, 참여 코드, 내 닉네임/전공
   - 본문은 "마인드맵이 곧 여기에 표시됩니다" 플레이스홀더
   - 아직 업로드 폼/트리는 구현하지 않는다 (06단계)

================================================================
프론트 상태
================================================================
localStorage에 저장:
  prizm.memberId
  prizm.spaceId
  prizm.nickname
  prizm.school
  prizm.major
  prizm.joinCode

새로고침해도 같은 스페이스로 복귀할 수 있어야 한다.
memberId가 없거나 다른 스페이스의 member면 join 화면으로 보낸다.

API 호출은 fetch 또는 axios. 에러 메시지를 화면에 보여준다.
스타일은 깔끔한 단일 톤이면 충분하다. 디자인 시스템 구축은 하지 않는다.

================================================================
하지 말 것
================================================================
- 실제 로그인, 프로필 페이지, 랜딩 마케팅 페이지를 만들지 않는다.
- 마인드맵 라이브러리를 이 단계에서 도입하지 않는다.
- 업로드 UI는 다음 단계다.

================================================================
완료 기준
================================================================
- 브라우저만으로 스페이스 생성 → 코드 확인 → 다른 프로필로 join 이 된다.
- 잘못된 코드면 에러가 보인다.
- /spaces/:id 헤더에 이름과 코드가 표시된다.
- localStorage 기반으로 새로고침 후 복귀가 된다.
