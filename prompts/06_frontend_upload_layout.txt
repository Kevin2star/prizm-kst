================================================================
제품 컨텍스트
================================================================
업로드 필수값은 제목 + 본문뿐이다.
업로드 직후 화면이 멈추면 안 된다. 서버는 PENDING을 즉시 반환하므로,
프론트는 "분석 중" 상태를 노드 또는 토스트로 보여준다.

================================================================
레이아웃
================================================================
/spaces/:spaceId 를 좌우(또는 상하) 분할한다.

왼쪽 (또는 상단): 업로드 패널
  - 제목 input
  - 본문 textarea
  - 제출 버튼
  - 성공 시 폼 비우기
  - 제출 중 버튼 disable
  - 파일 첨부 UI는 만들지 않는다 (P1)

오른쪽 (메인): 캔버스
  - 루트 노드: 스페이스 이름
  - 아직 그룹이 없으면 루트만 보이거나, PENDING/READY 결과물을
    루트 바로 아래 임시 잎 노드(또는 단순 리스트)로 표시
  - 접기/펼치기 상호작용은 10단계에서 본격 구현한다.
    지금은 구조가 들어갈 자리와 데이터 바인딩만 있으면 된다.

하단 또는 사이드: 최근 업로드 목록
  - title, 작성자 닉네임, status (PENDING / READY / FAILED)

원문 보기
  - 목록 항목 클릭 시 오른쪽 패널 또는 모달에 title + content + 작성자 소속 표시
  - "소스 1개 보기"의 전신이다.

================================================================
데이터
================================================================
- 마운트 시 GET /api/spaces/{id}/artifacts 로 기존 항목을 불러온다.
- POST 성공 시 목록에 낙관적 추가(status=PENDING).
- 아직 WebSocket이 없으므로, PENDING 항목은 3초 간격 폴링으로 상태를 갱신해도 된다.
  (11단계에서 WebSocket으로 교체할 것이므로 폴링은 한 곳에 모아 둔다.)

================================================================
하지 말 것
================================================================
- D3 force-directed 그래프, Cytoscape 복잡한 레이아웃을 도입하지 않는다.
  PRD는 트리 레이아웃을 명시했다. 힘-방향 그래프는 금지.
- 비교 정리본 UI(공통점/차이점/비고)는 그룹 API가 없는 지금은 플레이스홀더만.
- Gemini를 프론트에서 직접 호출하지 않는다.

================================================================
완료 기준
================================================================
- 제목+본문을 올리면 목록에 PENDING으로 나타난다.
- 새로고침해도 기존 업로드가 보인다.
- 항목을 누르면 원문이 읽힌다.
- 메인 캔버스에 스페이스 루트 노드가 보인다.
