================================================================
제품 컨텍스트
================================================================
유사도 임계값(0.75 권장) 이상인 항목끼리 자동 그룹을 형성한다.
그룹에 2개 이상 모이면 AI가 정리본을 만들되, 하나로 뭉뚱그리지 않고 네 갈래로 보여준다.

  그룹 라벨  — 예: "대기시간 문제 해결"
  공통점    — 모든 항목이 공유하는 핵심 문제의식 1~2줄
  차이점    — 항목별로 "누가 / 어떤 관점으로 / 무엇을 다르게" 접근했는지 목록
  비고      — 아직 아무도 다루지 않은 빈틈, 특이하게 튀는 접근, 확장 아이디어

각 갈래는 근거가 된 원본으로 연결되어야 한다. 근거 없는 요약을 만들지 말라는 것이 PRD 핵심이다.

================================================================
그룹핑 알고리즘 (단순하게, 벡터DB 없이)
================================================================
새 Artifact가 READY가 되면, 같은 Space의 다른 READY 항목을 전부 읽어 코사인 유사도를 계산한다.

배정 규칙:
  1) 가장 유사한 항목의 유사도가 0.75 미만이면 그룹에 넣지 않는다. (단독 잎 노드)
  2) 그 항목이 이미 그룹에 속하면 같은 groupId를 부여한다.
  3) 그 항목이 단독이면 새 Group을 만들고 두 항목을 넣는다.
  4) 여러 그룹과 동시에 0.75 이상이면 "가장 높은 유사도 1개"만 따른다. (다중 그룹 금지)
  5) 임계값은 application.yml 의 prizm.similarity-threshold=0.75 로 빼 둔다.
     데모 데이터가 이상하면 코드가 아니라 설정/데이터로 맞춘다.

정리본 생성 시점:
  - 그룹 멤버가 2건이 되는 순간 최초 생성
  - 3건 이상 합류할 때마다 재생성
  - 1건만 있는 그룹은 만들지 않는다 (배정 규칙상 1건 그룹은 없어야 함)

================================================================
정리본 Gemini 호출
================================================================
모델: gemini-2.5-flash
입력: 그룹 내 각 Artifact의 title, content, nickname, school, major, tags
출력 JSON만:
  {
    "label": "대기시간 문제 해결",
    "commonPoints": "...",
    "differences": [
      { "artifactId": 101, "summary": "민수(산업공학)는 동선 관점에서 대기열을 재배치했다" }
    ],
    "notes": "..."
  }

프롬프트에 반드시 넣을 제약:
  - 하나로 합치지 말고 차이를 보존하라
  - 차이점은 "누가 / 어떤 관점으로 / 무엇을 다르게" 형식
  - 원문에 없는 사실을 만들지 마라
  - notes는 빈틈/특이점/확장만. 없는 칭찬을 지어내지 마라

commonPoints / differences / notes 는 Group 컬럼에 저장한다.
differences는 JSON 문자열로 저장해도 된다.

================================================================
API
================================================================
GET /api/groups/{id}
  response: {
    "id": 1,
    "spaceId": 1,
    "label": "...",
    "commonPoints": "...",
    "differences": [...],
    "notes": "...",
    "artifacts": [
      { "id": 101, "title": "...", "memberNickname": "민수", "school": "...", "major": "..." }
    ]
  }

이 엔드포인트가 "소스 N개 보기"의 근거 목록이다.

하지 말 것
================================================================
- 커뮤니티 디텍션, HDBSCAN 등 복잡한 클러스터링을 쓰지 않는다. 선형 전체비교면 충분하다.
- 그룹을 사람이 수동으로 편집하는 UI/API를 만들지 않는다.
- WebSocket 이벤트는 11단계다. 지금은 DB만 갱신한다.

완료 기준
================================================================
- 비슷한 두 글을 올리면 같은 groupId를 갖고 label/commonPoints/differences/notes가 채워진다.
- 전혀 다른 글은 그룹에 들어가지 않는다.
- GET /api/groups/{id} 로 정리본과 원본 목록을 볼 수 있다.
- 임계값이 설정으로 분리되어 있다.
