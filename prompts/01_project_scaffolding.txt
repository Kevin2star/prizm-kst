역할: 시니어 풀스택 엔지니어. 해커톤(26시간)용 프로젝트를 처음부터 세팅한다.
선행 단계: 없음. 이 파일이 첫 단계다.
이번 단계 목표: Supabase(Edge Functions) + 프론트(React)를 한 저장소에서 실행 가능하게 만든다.
다음 단계: 02_data_model.txt

================================================================
제품 컨텍스트
================================================================
팀원을 초대한 공유 스페이스에 각자 결과물을 올리면, AI가 자동으로 분석·비교해
하나의 시각화된 정리본으로 만들어주는 협업 플랫폼이다.
이번 단계에서는 기능 구현을 하지 않는다. 실행 가능한 골격만 만든다.

================================================================
기술 스택 (변경 금지)
================================================================
- 백엔드: Supabase Edge Functions. Spring Boot를 만들지 않는다.
- DB: Supabase Postgres. 로컬 MySQL/Postgres 설치는 하지 않는다.
- 프론트: React (Vite 권장), JavaScript 또는 TypeScript
- 패키지 매니저: 프론트는 npm
- 벡터DB / Redis / Docker 오케스트레이션은 아직 도입하지 않는다.
- Supabase Auth로 제품 로그인을 만들지 않는다. Gemini는 Functions secret으로만 호출한다.

권장 디렉터리 구조:
  /frontend    React (Vite)
  /supabase    migrations, functions, seed.sql
  /prompts     (이미 존재, 스택 문구만 맞출 것)
  README.md

================================================================
구현할 것
================================================================
1) supabase
   - migrations로 spaces/members/artifacts/artifact_groups 테이블
   - Edge Function prizm-api: GET /health → { "status": "ok" }
   - Gemini 키는 Functions secret. 프론트 VITE_에 넣지 않는다.

2) frontend
   - Vite + React 앱
   - 개발 서버 포트 5173
   - VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY
   - 임시 홈 화면: 프로젝트 이름과 "스페이스 만들기 / 참여하기" 자리만 표시
     (실제 폼 로직은 05단계에서 구현)

3) 루트 README.md
   - 한 줄 정의
   - 사전 요구사항 (Node, Supabase 프로젝트 + anon key)
   - Functions 배포 / frontend 실행 명령
   - 환경변수 목록

================================================================
하지 말 것
================================================================
- 엔티티, API, Gemini 연동, WebSocket, 시각화를 이 단계에서 구현하지 않는다.
- 로그인/회원가입/OAuth를 만들지 않는다. 이 서비스는 로그인 없이 코드로 입장한다.
- Docker Compose는 필수가 아니다. Supabase 호스티드 Postgres를 쓴다고 가정한다.
- 불필요한 라이브러리를 미리 설치하지 않는다.
