================================================================
제품 컨텍스트
================================================================
정리본을 글이 아니라 그림으로 보여주는 것이 이 서비스의 얼굴이다.
구조: 루트 → 그룹 → (공통점 / 차이점 / 비고 / 원본 목록)
각 노드는 화살표(>)로 접혀 있다가 클릭하면 펼쳐진다.
처음엔 전체 구조만 한눈에 보이고, 필요한 가지만 파고든다.

힘-방향(force-directed) 그래프는 사용하지 않는다.
26시간 안에 안정적으로 구현되고, NotebookLM을 써본 사람에게 학습 비용이 없기 때문이다.

================================================================
시각화 요구사항
================================================================
1) 데이터: 마운트 시 GET /api/spaces/{id}/graph
2) 레이아웃: 수평 또는 수직 트리. 라이브러리는 자유
   권장: 직접 렌더하는 재귀 트리 컴포넌트 (가장 안전)
   허용: react-d3-tree 등 트리 전용 라이브러리
   금지: force-directed (d3-force 네트워크, Cytoscape cose 등)
3) 기본 상태: 루트와 그룹 라벨만 펼침. 4갈래 하위는 접힘.
4) 노드 클릭:
   - GROUP/COMMON/DIFF/NOTES/SOURCES: 토글 펼침
   - ARTIFACT: 원문 패널 오픈 ("소스 1개 보기") → GET /api/artifacts/{id}
   - COMMON/DIFF/NOTES 옆에 "소스 N개 보기" 링크 → 해당 sourceArtifactIds 목록
5) 소속 색상 태그:
   - school+major 조합 또는 major 기준으로 노드에 색 점/뱃지
   - 범례를 캔버스 모서리에 둔다 ("전공 간 교류"를 눈으로 보여 주는 장치)
6) 상태 표시:
   - PENDING/PROCESSING: 작은 스피너 또는 "분석 중"
   - FAILED: 경고 표시
   - GROUP.updated == true: "업데이트됨" 배지
7) 새 그룹은 루트 아래 새 가지로 나타난다. 전체 재배치 애니메이션은 필요 없다.

원문 패널
  - 제목, 작성자(닉네임/학교/전공), 태그, 본문
  - 닫기 버튼
  - 근거 없는 요약이 아니라 원본을 바로 열 수 있어야 한다

================================================================
하지 말 것
================================================================
- 노드 드래그 이동 (P2, 잘라도 무방)
- 줌/팬을 과도하게 구현하느라 트리 토글이 불안정해지는 것
- 시각화가 실패하면 앱 전체가 흰 화면이 되게 두지 말 것.
  트리 렌더 에러 시 그룹 카드 목록으로라도 내용을 보여 주는 안전망을 둔다.
  (13단계 다운그레이드의 전신)

================================================================
완료 기준
================================================================
- 사전 데이터가 있는 스페이스에서 루트-그룹-4갈래 트리가 한눈에 보인다.
- 그룹을 펼치면 공통점/차이점/비고/원본이 순서대로 드러난다.
- 잎 노드 클릭 시 원문이 열린다.
- 전공별 색이 범례와 함께 보인다.
- force-directed 그래프가 코드에 없다.
