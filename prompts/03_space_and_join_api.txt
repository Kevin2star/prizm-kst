================================================================
제품 컨텍스트
================================================================
생성자가 스페이스를 만들면 6자리 참여 코드가 발급된다.
참여자는 닉네임 + 소속(학교/전공)만 입력하고 입장한다. 로그인은 없다.
소속 정보는 이후 시각화에서 색상 구분에 쓰여 "전공 간 교류"를 보여준다.

================================================================
API 스펙
================================================================
POST /api/spaces
  request:  { "name": "교내 카페 개선안" }
  response: { "id": 1, "name": "...", "joinCode": "A3K9Q2" }
  - joinCode: 영문 대문자 + 숫자 6자리, 충돌 시 재생성
  - name은 공백이면 400

POST /api/spaces/{code}/join
  request:  { "nickname": "민수", "school": "한국대", "major": "산업공학" }
  response: { "memberId": 10, "spaceId": 1, "nickname": "민수", "school": "한국대", "major": "산업공학" }
  - code는 대소문자 무시하고 대문자로 정규화
  - 없는 코드면 404
  - nickname, school, major 중 하나라도 비면 400

GET /api/spaces/{id}
  response: { "id": 1, "name": "...", "joinCode": "A3K9Q2", "memberCount": 3 }
  - 이후 프론트가 헤더에 스페이스 이름/코드를 띄우기 위해 필요하다.

에러 응답은 일관된 JSON으로 한다. 예: { "error": "SPACE_NOT_FOUND", "message": "..." }

================================================================
구현 규칙
================================================================
- 세션/JWT/쿠키 로그인을 만들지 않는다.
- 프론트는 memberId를 localStorage에 들고 이후 요청에 실어 보낸다.
  이번 단계에서는 서버가 memberId를 발급해 주기만 하면 된다.
- 코드 생성은 암호학적으로 완벽할 필요 없다. 6자리 + unique 제약이면 충분하다.
- 컨트롤러는 얇게, 비즈니스 로직은 서비스에 둔다.
- 단위 테스트는 필수는 아니지만, joinCode 중복 재시도 로직은 꼭 검증 가능하게 작성한다.

================================================================
하지 말 것
================================================================
- 초대 링크 토큰 시스템을 거창하게 만들지 않는다. 코드 입장이 P0다.
- 이메일, 비밀번호, 소셜 로그인을 추가하지 않는다.
- Artifact / Group API는 다음 단계다.

================================================================
완료 기준
================================================================
- 스페이스를 만들면 6자리 코드가 나온다.
- 그 코드로 join 하면 Member가 저장되고 memberId가 반환된다.
- 잘못된 코드는 404, 필수값 누락은 400이다.
- GET /api/health 와 기존 골격이 깨지지 않는다.
